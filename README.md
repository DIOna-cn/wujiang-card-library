# 武将牌库

把 `素材\` 文件夹里的武将卡牌素材整理成一个可以直接浏览、并且**能在网页上编写武将信息**的本地工具。

- **卡图尺寸与带技能的武将牌完全一致**（1465×2055 的比例），所以之后把「不带技能的卡图」放进文件夹，卡图会原位替换、不会跳动
- 点击卡图可以看到基本信息与技能描述，**技能和基本信息都能在网页上直接改，改完保存就写回文件**
- 支持**新建武将**、**标签分类**、搜索、势力筛选

## 一、启动

双击 **`启动.cmd`**。

会自动打开浏览器到 <http://127.0.0.1:3456/>，命令行窗口保持开启即为运行中。
关掉那个窗口（或双击 `停止.cmd`）即停止服务。

> 需要 Node.js（已确认本机为 v22）；「上传 / 下载」还需要 Git。服务只监听 `127.0.0.1`，不对外网开放，零第三方依赖。

### 如果双击没反应 / 窗口闪退

启动器分两层，方便定位问题：

| 文件 | 作用 | 编码要求 |
| --- | --- | --- |
| `启动.cmd` / `停止.cmd` | 双击入口，负责找到 node 并把控制权交给下面对应的 ps1 | **必须是纯 ASCII** |
| `start.ps1` / `stop.ps1` | 真正的启动/停止逻辑与中文提示 | **必须是 UTF-8 with BOM** |

之所以要这样分开：cmd.exe 是按系统 ANSI 代码页（简体中文环境是 GBK）**逐字节**解析 `.cmd` 文件的，`chcp 65001` 也改不了已经加载的批处理的解析方式。所以 `.cmd` 里只要出现非 ASCII 字节，就会被拆成乱码命令、脚本中途夭折，表现为"窗口闪一下就没了"。中文提示因此全部搬进 `.ps1`；而 `.ps1` 反之必须带 BOM，否则 Windows PowerShell 5.1 会按 ANSI 解码、中文变乱码。

**改这两个 `.cmd` 时请只用英文注释**，别把中文加回去。

实在起不来时，直接开一个 PowerShell 窗口手动跑，这样能看到完整报错：

```powershell
cd E:\Deepseek\武将牌库
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

> 本机没有 PowerShell 7（`pwsh`），只有 Windows PowerShell 5.1，`启动.cmd` 会自动回退到后者，不用管。

## 二、网页上能做什么

### 浏览
| 操作 | 说明 |
| --- | --- |
| 左侧「原作」 | 出自哪部作品（明日方舟 / 东方Project / 原神 / 三国杀 / 原创…）。**单选**——一个武将只能有一个原作，点另一个会直接替换，再点一次取消 |
| 左侧「标签」 | 玩法特性（过牌 / 输出 / 增益 / 减益 / 生存…）。**多选**，可叠加筛选 |
| 左侧「势力」 | 按魏蜀吴群晋神妖魂筛选 |
| 顶部搜索框 | 搜武将名、称号、技能名、技能描述、编号、原作、标签（按 `/` 快速聚焦） |
| 「只看待补」 | 只列出缺卡图 / 缺描述 / 没技能的武将 |
| 「只看待实现」 | 只列出 `implemented: false` 的武将，也就是卡片带橙色外框的那些。和「只看待补」一样是独立开关，两个都勾就是交集 |
| 「卡图 / 列表」 | 两种浏览视图 |
| 点卡图 | 右侧滑出详情：卡图、基本信息（含原作）、技能、引文、备注、附加内容、图片与语音素材 |

卡面上**原作**用蓝色小片、**标签**用金色小片分开显示，**点这两个小片即可直接按它筛选**（不会误打开详情）。

**衍生技**在技能列表里单独一种外观：整体缩进 + 左侧虚线 + 名字前带「衍生」角标，颜色偏青，和本体技能一眼可分（卡面的技能小片也用虚线青色 + 空心点标记）。

技能描述里的三类东西会自动上色，方便一眼扫读：**技能类型词**（锁定技 / 觉醒技 / 转换技…）金色、**【牌名】**蓝色、**引号里的专名**（「神宝」、“魂”、“摄影车”、“迷彩-基本”…）紫色。引号认全角的 `「」『』“”‘’` 和半角的 `""`（半角只认成对的双引号，`it's` 这种撇号不会被误伤）；引号不成对、空引号、或括了 40 字以上的都不标，免得把整段吞掉。上色只影响显示，`武将.json` 里的原文一个字都不动。

**「待实现」**（设计还没做完的武将）只在卡图外框上加一圈橙色描边、卡图左下角加一个「待实现」角标，点开详情还有一条说明。**刻意不加到牌底的标签区** —— 那里已经挤着原作、特性标签和技能小片，再混一个状态进去就分不清哪些是玩法特性了。标不标在编辑界面里勾，存在 `武将.json` 的 `implemented` 里（**缺省 = 已实现**）。

### 编写 / 修改
1. 点开一个武将 → 右上角 **「编辑」**
2. 改基本信息（含**原作**）、卡图文件名、技能名与技能描述、**标签**；技能可增删、上下移、标为衍生技
3. **「保存」**（或 `Ctrl+S`）→ 立即写入该武将文件夹里的 `武将.json`

编辑能力：
- **多卡面**：一个武将有多张武将牌（结城理三张面具、普瑞赛斯两张、塔露拉觉醒前后）时，在「卡面」区用 `＋` 加一张，各自有独立的卡图与技能表
- **设为主图**：在「图片素材」里鼠标移到任意图片上，点「设为主图」，即可把它指定为这张卡面的主图
- **上传图片**：点「图片素材」右上角的 ⬆，图片会直接存进该武将文件夹
- **导入图片**：卡图那两栏（无技能卡图 / 带技能卡图）各有一个「导入图片」按钮，选一张本地图就直接上传到该武将文件夹并填进那一栏，省掉「先传进素材库、再去图库里点设为主图」两步
- **原作与标签**：详情里分成两个输入项——原作（单个，带候选下拉）/ 标签（多个，回车添加）。侧栏「＋」打开的弹窗里维护的是两张清单本身，改名会同步更新所有武将
- **衍生技**：技能行右侧勾「衍生技」，该技能立刻变成衍生技外观，并在卡面技能小片上标记

### 新建 / 删除
- 顶部 **「＋ 新建武将」**：会在 `素材\` 下建文件夹并写好 `武将.json`。弹窗里有个「待实现」勾选框，勾上就先占位、卡片带橙色外框
- 详情里 **「删除」**：整个武将文件夹移入 `.data\回收站\`，可还原

### 导出为 shap（做卡工程档）
详情右上角 **「导出为 shap」**。弹窗会先列清楚「这次会用网页上的内容覆盖哪些字段」，确认无误再点「下载 .shap」。

- **本来就有工程档的武将**：拿那个 `.shap` 当骨架，只覆盖文字（武将名 / 称号 / 势力 / 体力 / 上限 / 护甲 / 编号 / 台词 / 版权 / 主公标记 / 技能名与描述），**立绘和你在做卡软件里拖出来的排版原样保留**。文件名沿用原工程档名，导完放回素材目录正好覆盖原件
- **还没有工程档的武将**（芙兰朵露、重岳、黍…）：借用一份默认骨架，并把该卡的主图内嵌进去。**但立绘位置、技能框高度要自己在做卡软件里重摆** —— 默认骨架只保证能正常打开
- **多卡武将**（结城理三张面具）：按卡名各自找对应的工程档，一张卡一个文件
- **专名自动加粗**：网页上会标色的三类内容（技能类型词、【牌名】、引号里的专名），写进工程档时左右会包上 `<b></b>`，做卡软件出图就是加粗的。改的只是导出产物，`武将.json` 里仍是没有标签的纯文本；反复导出不会越包越多层，加粗位置也和网页上的标色一一对应 —— 这两份规则分别在 `web\app.js` 和 `server\shap-export.mjs` 里，回归脚本有交叉检查盯着它们别跑偏
- 导出**不改动素材目录**，只是下载一个文件

为什么不能凭空生成：`.shap` 确实是纯文本 JSON、模板也统一（`new_ui_zhuoyue`），但 `renderConfig` 里装的全是人工细节 —— 立绘的位移与缩放、技能框高度、字号字距。对比煌和塔露拉，光立绘就是 `x=-67.34 / scale=2.35` 与 `x=4.75 / scale=1` 的区别。这些推不出来，只能从已有工程档里继承。默认骨架借的是塔露拉那份（立绘 `scale=1` 接近原样摆放、技能框又是最高的一档，新建武将技能少不会溢出），存在 `server\shap-default.json`，想换直接替换它即可。

## 三、数据存在哪

**每个武将的描述文件就是他自己文件夹里的 `武将.json`**，和卡图放在一起：

```
素材\
├─ 黍\
│  ├─ 武将.json        ← 描述文件（在网页上编辑的就是它）
│  ├─ 立绘.png          ← 无技能卡图（主图）
│  └─ ...
├─ 陈\
│  ├─ 武将.json
│  ├─ 立绘.png
│  └─ 新UI.龙门警司.陈.png   ← 带技能卡图（备查）
├─ 胡桃\
│  ├─ 武将.json        ← 里面写着 "implemented": false，也就是「待实现」
│  └─ ...
└─ _待整理\              ← 下划线开头的是归类目录，不会被当成武将
```

### `武将.json` 字段说明

```jsonc
{
  "schema": 1,
  "id": "黍",                 // 由文件夹定位，网页不可改
  "dir": "黍",

  "name": "黍",               // 武将名
  "title": "怀黍离",           // 称号
  "kingdom": "wei",           // 势力：wei shu wu qun jin shen yao hun（空字符串=未设）
  "hp": 3,                    // 体力
  "maxHp": 3,                 // 体力上限
  "shield": 0,                // 护甲
  "gender": "",               // 男 / 女 / 空
  "quality": "epic",
  "legendId": "",             // 编号，如 "ARK 012"
  "quote": "",                // 卡面底部的角色台词
  "copyright": "",
  "isLord": false,            // 是否主公
  "implemented": false,       // ★ 是否已实现：false = 待实现（卡片外框橙色、带角标）。
                              //   不写这一项就等于已实现，所以旧文件一个都不用改
  "origin": "明日方舟",        // ★ 原作：单值，只能有一个（"原创" / 留空表示未定）
  "tags": ["生存", "过牌"],     // ★ 特性标签：多值（过牌 / 输出 / 增益 / 减益…）
  "note": "",                 // 备注：设计思路、实现说明，只在这里显示，不上卡面

  "cards": [                  // 卡面列表；一个武将多张武将牌就写多条
    {
      "name": "",             // 卡面名，如 "面具①" / "觉醒后"；单卡面留空
      "image": "立绘.png",     // ★ 无技能卡图（网页显示的主图）
      "cardImage": "新UI.xxx.png", // 带技能卡图（备查；主图缺失时顶替）
      "legendId": "TH 001",   // 本卡面编号
      "skills": [
        {
          "name": "春种",
          "desc": "出牌阶段限一次，……",  // 换行会保留；【杀】这类牌名会自动高亮
          "derived": false,      // true = 衍生技（显示虚线标记）
          "fixNote": ""          // 可选：这句话的订正记录
        }
      ],
      "derived": [],          // 衍生技名列表（一般不用手填，skills[].derived 就够）
      "note": ""              // 本卡面备注
    }
  ],

  "extras": [                 // 附加内容：如辉夜的「神宝」，在详情页单独成区
    {
      "title": "神宝（衍生装备牌）",
      "kind": "treasure",
      "note": "",
      "items": [
        { "name": "蓬莱的弹枝", "upgradedName": "蓬莱的玉枝",
          "image": "../宝物卡图/蓬莱的玉枝.♥.A.png", "icon": "蓬莱的弹枝.png",
          "suit": "♥.A", "desc": "锁定技，……" }
      ]
    }
  ],

  "gallery": [ /* 素材清单，网页自动扫描生成，不用手改 */ ],
  "sounds":  [ /* 语音分组，自动生成 */ ],
  "source":  { /* 首次导入的来源记录 */ }
}
```

> `gallery` / `sounds` / `cards[].displayImage` 这类字段由服务端**读取时现算**，手写错了也不要紧；
> 但 `image` / `skills` / `note` 这些是你真正要维护的内容。

### 关于「不带技能的卡图」

目前素材里**没有**纯粹的「不带技能卡图」，能顶上的是各武将的 `立绘.png` / `立绘.jpg`（纯人物图、无技能文字）。网页的取图优先级是：

1. `cards[].image` —— 你指定的无技能卡图
2. `cards[].cardImage` —— 带技能卡图（网页会打上「带技能卡图」角标）
3. 都没有 → 显示占位符，并提示该把卡图放进哪个文件夹

所以补图很简单：把不带技能的卡图丢进对应武将文件夹，在网页上点「编辑 → 设为主图」，或者直接把文件名填进 `image`。

卡图容器固定按 **1465 : 2055** 显示（`web/style.css` 里的 `--card-ratio`），和带技能武将牌同比例。

## 四、目录结构

```
武将牌库\
├─ 启动.cmd              双击启动（纯 ASCII，真正逻辑在 start.ps1）
├─ 停止.cmd              双击停止（纯 ASCII，真正逻辑在 stop.ps1）
├─ start.ps1  stop.ps1   启动 / 停止逻辑与中文提示（UTF-8 with BOM）
├─ 数据迁移差异报告.md     ！迁移时发现的、需要你裁决的差异都在这里
├─ server\server.mjs      本地服务：扫描素材、读写 武将.json、提供图片
├─ web\                   网页（index.html / style.css / app.js，无构建步骤）
├─ scripts\
│  ├─ import.mjs          从 .shap 工程档 + 描述.txt 生成 武将.json（含人工订正表）
│  ├─ migrate-origin.mjs  把混在 tags 里的原作拆到独立的 origin 字段（幂等）
│  ├─ migrate-pending.mjs 把 素材\_待实现\<武将> 挪成平级并写上 implemented（幂等）
│  ├─ mark-derived.mjs    给指定技能打「衍生技」标记（只动目标文件，不覆盖其它编辑）
│  ├─ check-migration.mjs 逐条比对旧 描述.txt 与 武将.json，查有没有迁移丢信息
│  ├─ verify.mjs          无头浏览器端到端自检（30 项）
│  ├─ verify-crud.mjs     新建/编辑/删除/待实现标记/原作与标签表自检（20 项，自动清理与还原）
│  ├─ verify-shap-export.mjs  导出为 .shap 的自检（53 项，盯「只动文字、保住人工排版」）
│  ├─ verify-desc-render.mjs  技能描述上色与转义的自检（21 项）
│  ├─ verify-sync-progress.mjs 同步进度显示的自检（59 项：解析 / 累加器 / 轮询 / 界面 / 窄栏排版）
│  └─ shots.mjs           抓界面截图到 _shots\
└─ .data\                 运行数据（原作与标签清单、站点配置、回收站、原始描述备份、server.pid）
```

> `.data\原始描述备份\` 是 24 份原始 `描述.txt` 的唯一留存（素材目录里那份已按你的要求删掉并入回收站）。
> **别删它**；需要复核时 `node scripts\check-migration.mjs` 就是从这个目录读的。

`停止.cmd` 靠 `.data\server.pid` 找到服务进程（服务启动时自己登记，停止后自动删除）。
**不要**改成"扫描命令行里含某个关键词的进程"——那样会误杀命令行里恰好带着同样文本的无关进程，这个坑已经踩过一次。

## 五、数据是怎么来的（迁移说明）

1. 素材里 **18 个 `.shap` 工程档**是卡牌制作工具的存档，里面有卡面上真正印着的结构化数据（武将名/称号/势力/体力/护甲/编号/技能名+描述/引文/版权），作为**首选来源**。
2. 没有工程档的武将（乌啾、夕、年、安洁莉娜、涤火杰西卡、均1、均2、黍、颉、重岳、普瑞赛斯、锏…）从 `描述.txt` 解析。
3. 两边不一致的地方，以及 `描述.txt` 里的笔误、断行，集中在 `scripts/import.mjs` 的 `MANUAL` 订正表里逐条处理，每处都在 `武将.json` 的 `fixNote` / `note` 里留了记录。
4. 原 `描述.txt` 已全部备份到 `.data\原始描述备份\`（文件名里的 `__` 代表路径分隔符），随后按你的要求统一成 `武将.json`。
5. **原作与标签原本混在同一个 `tags` 数组里**，已由 `scripts/migrate-origin.mjs` 拆开：原作进 `origin`（单值），特性标签留在 `tags`（多值）。这个脚本是幂等的，重复跑不会重复改动。
6. **「待实现」原本靠把武将放进 `素材\_待实现\` 表达**，已由 `scripts/migrate-pending.mjs` 改成平级放置 + `武将.json` 里的 `implemented` 字段（胡桃、觉、锏 三个）。目录位置不该承载语义：那样它们在网页上的目录标识是 `_待实现/胡桃`，跟别的武将不是一个形状，导出 `.shap`、同步、图片 URL 都得跟着多认一层。

**⚠️ 请先看 [`数据迁移差异报告.md`](数据迁移差异报告.md)**：有 3 位武将（藿藿、遥、塔露拉）的卡面与 `描述.txt` 数值不一致，疑似设计更新过但卡面未重新导出，需要你确认哪版为准。

### 重新导入

```powershell
cd E:\Deepseek\武将牌库
node scripts\import.mjs            # 只生成还没有 武将.json 的武将
node scripts\import.mjs --dry      # 只预览结果，不写文件
node scripts\import.mjs --force    # 全部重生成（★ 会覆盖网页里的编辑）
```

新增武将文件夹后，网页点「↻ 重新扫描」即可看到（切回窗口时也会自动检测）。

### 自检

```powershell
node scripts\verify.mjs            # 端到端检查：渲染、图片、编辑保存落盘、搜索筛选、只看待实现
node scripts\verify-crud.mjs       # 新建 → 编辑 → 标签 → 删除进回收站（用临时武将，自动清理）
node scripts\verify-sync.mjs       # 同步面板：三个按钮、状态、设置弹窗
```

## 六、复制给别人用

1. **两个文件夹并排放**（结构不能改）：

4. 服务只监听 `127.0.0.1`，**只有对方本机能访问**。想让局域网里的人访问得改 `server\server.mjs` 里的 `HOST`，但那等于把"能读写别人磁盘文件"的接口开放出去，不建议。

## 七、远程共享（GitHub）

仓库：<https://github.com/DIOna-cn/wujiang-card-library>（公开）

**三种用法，随你方便**：网页侧栏的三个按钮、双击那两个 `.cmd`、或者命令行。

### 网页里直接点（推荐）

侧栏最上面就是「远程同步」面板（放最前面，不会被长长的标签列表挤到看不见）：

```
● 已是最新          5d4c187              ← 状态圆点 + 当前提交
DIOna-cn/wujiang-card-library @main       ← 点它打开仓库页面
┌───────┬───────┬───────┐
│ ⟳检查  │ ↓下载  │ ↑上传  │              ← 有新内容时「下载」会变绿
└───────┴───────┴───────┘
          上次检查 3 秒前
```

跑起来的时候，同一个位置会变成这样：

```
● 正在上传…                               ← 圆点会呼吸
DIOna-cn/wujiang-card-library @main
┌───────┬───────┬───────┐
│ ⟳检查  │ ↓下载  │ ↑上传  │              ← 进行中三个按钮都禁用
└───────┴───────┴───────┘
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━             ← 按真实百分比走
52%                             1 分 16 秒 ← 已用时间（秒表一直在跳）
132 / 270 个文件 · 87.30 MB / 163.60 MB   ← 这一步的量化进度
  ✓ 准备工作副本…
  ✓ 收集要同步的文件…
  ⟳ 写入工作副本（共 270 个文件）…          ← 当前这步在闪
```

- **检查**：问一次远端有没有新提交。其实不用手动点——页面**每 60 秒自动轮询**
- **上传**：把你在这里的改动推上去（等于 `推送到GitHub.cmd`）
- **下载**：把远端的更新拉回来写进本地（等于 `从GitHub拉取.cmd`）
- 面板右上 **⚙** 可改仓库地址、分支、同步范围、轮询间隔、代理、工作副本位置

状态含义：

| 显示 | 意思 |
| --- | --- |
| 🟢 已是最新 | 本地与远端一致 |
| 🟡 远端有新内容 | 别人推了新东西，点「下载」（该按钮会变绿） |
| 🟡 有 N 处改动未上传 | 你改了还没推，点「上传」 |
| 🟡 有 N 个提交没上传 | 本地有远端没有的提交——**下载合并之后留下的那个 merge commit 就是这样**，点「上传」推上去 |
| 🔴 连不上远端 | 先点 ⚙ 看代理设置：系统代理关着时会走直连，填了代理却连不上会自动改直连重试 |
| 🔵 正在检查 / 上传 / 下载… | 进行中，下方是进度条、秒表、当前步骤和一份步骤清单 |
| 🔴 报 `EPERM ... mkdir 'C:\Users\某人'` | ⚙ 里的「git 工作副本位置」是上一台机器留下的绝对路径，**清空它**即可；新版会自动退回默认位置 |
| 🔴 报 `spawn git ENOENT` 或「找不到 git」 | 这台电脑上没装 Git，或者**服务是在装 Git 之前启动的** —— 装好后重启服务 |

#### 进行中的那几样东西

| 看什么 | 说明 |
| --- | --- |
| **进度条 + 百分比** | 按阶段加权推进，不是装饰动画。**没真正跑完不会显示 100%** —— 上传撞上分叉会多走一轮「合并 + 再推」，权重加起来超过 100%，不夹住的话进度条能冲到 120% 再退回来，那比没有进度条还让人摸不着头脑 |
| **秒表** | 已用时间。推 / 拉那一段要等 github，说不准多久；有秒表在跳就知道没卡死 |
| **明细行** | 当前这一步的量化进度。写文件时是 `132 / 270 个文件 · 87.30 MB / 163.60 MB`；联网时借 git 自己报的数，例如 `接收对象 45%（1234 / 2741）` |
| **步骤清单** | 走过的打勾、当前那步在闪。**出错时会留着**，好知道是卡在哪一步上 |

首次下载要把一百多 MB 拉下来，本来就慢；有这几个数在动，就不是干等。

> 任务跑着的时候轮询改成每 0.7 秒一次，**一直跟到任务结束**。
> 早先这里写死「最多 24 次」（约 21 秒），上传大文件时进度会半路冻住不动，
> 看着跟卡死一样 —— 这是实际发生过的事，`verify-sync-progress.mjs` 现在守着它。

> 别人推了新东西时，轮询会自动发现并弹提示（间隔 60 秒的情况下实测 18 秒内发现）。
> 页面切到后台时不轮询，切回来立刻查一次。

### 双击 `.cmd`

| 方向 | 入口 |
| --- | --- |
| **上传**（你 → 远端） | **`推送到GitHub.cmd`** |
| **下拉**（远端 → 你） | **`从GitHub拉取.cmd`** |

**日常就三句话**：

- 改完网页 → 点侧栏「上传」（或双击 `推送到GitHub.cmd`）
- 换台机器 / 别人改了 → 点侧栏「下载」（或双击 `从GitHub拉取.cmd`）
- 两边都改过 → **先推再拉**。直接拉会因为你本地也有改动而失败，这是故意的保护

> 一个必须知道的点：**你的项目目录（`E:\Deepseek\素材`）是数据源**，
> 远程同步走的是另一个 git 工作副本（默认 `%USERPROFILE%\<项目名>-git`，可在 ⚙ 里改）。
> 所以「下载」不是让 git 直接改写你的项目，而是先从远端更新工作副本，再把**数据文件**
> （`武将.json` / `tags.json` / 原始描述备份）逐个写回项目 —— 而且**只新增和更新、绝不删除**：
> 万一远端少了个武将文件夹，你本地那份不会消失。

> **换电脑时留意「git 工作副本位置」这一项**：它存的是**绝对路径**，落在 `.data\sync.json` 里。
> 这个文件不进仓库，但你**把整个项目文件夹拷到另一台电脑**时它会跟着走 —— 到了新机器上，
> 那个路径可能指向一个**根本不存在（或不属于你）的用户目录**，于是点「下载」只得到一句
> `EPERM: operation not permitted, mkdir 'C:\Users\某人'`，看不出是哪儿来的。
> 现在的行为：配置的位置建不出来就**自动退回本机默认位置**把活儿干完，并把新位置记进配置；
> 两个都建不出来才会报错，而且报的是一句告诉你「去 ⚙ 里清空这一项」的人话。
> 最省事的做法是换机器后顺手把这一项清空。

### 网络这一环

**`github.com` 直连是通的。** 2026-10 实测：DNS 正常解析、443 可连、`git ls-remote` 不加任何代理直接成功。

> 之前这里写着「直连被打断、必须挂代理走 `127.0.0.1:7892`」——**那个结论是错的**，
> 是被一个残留配置误导出来的。详见下面的坑。

git 默认不读 Windows 系统代理，所以规则是**以系统代理为准**：

- 系统代理**开着** → 自动跟随（每次跑都重读注册表，不是只在启动时读一次）
- 系统代理**关着** → 把 `http.proxy` / `https.proxy` 从工作副本的 git config 里**删掉**，走直连
- 想固定用某个代理：`--proxy http://127.0.0.1:<端口>`；想强制直连：`--no-proxy`
- 配了代理却连不上时，会**自动脱掉代理用直连再试一次**，而不是直接报失败

> **踩过的坑（已修）**：老写法是「没传 `--proxy` 就沿用 git config 里已有的代理」。
> 于是只要历史上配过一次，代理一关就**永远卡在那个死代理上**，报
> `Failed to connect to github.com port 443 via 127.0.0.1`。
> 这个现象太像「github 连不上」，以至于「直连是坏的」这个错误结论被写进了文档、
> 又反过来让人一直开着代理。`publish\verify-cli-merge.mjs` 的 [5][6] 两组现在专门守着它。

> 网络不通**完全不影响本地使用**：网页、编辑、保存、筛选、看图全是本地的，只有同步需要联网。

### 两个必须知道的坑（都已处理，但改脚本时别踩回去）

1. **`.gitattributes` 必须是 `* -text`**。Windows 上 Git 默认 `core.autocrlf=true`，提交时会把 CRLF 转成 LF，
   于是「仓库里的字节」和「本地文件的字节」不是同一份。`武将.json` 和图片全靠字节一致，
   一旦被转换就会出各种对不上的怪问题，而 `git status` 还是干净的。改完 `.gitattributes` 要
   `git add --renormalize -A`，并用 `git ls-files --eol` 确认全是 `attr/-text`。
   （`sync-repo.mjs` 每次推送都会自动做这个自检。）
2. **`git push` 报连接类错误不一定是真失败**。push 分「传对象」和「更新 ref」两阶段，
   若服务端已处理完、连接才在读取响应时被切断，git 会报错但推送其实生效了。
   看到错误先核对远端：`git -C <工作副本> ls-remote origin`，再决定要不要重推。

### 两个人同时改，会不会打架

**各建各的武将 —— 不会，自动合。** 你新建了 A、对方新建了 B，谁先点「上传」谁先上去；
后点的那个 push 会被远端拒绝（这就是"分叉"），程序会**自动把对方那份合进来、再推上去**，
结果是两边都有 A 和 B，各自的武将目录一个都不会少，也不用你先点「下载」再点「上传」。

实测见 `scripts/verify-merge.mjs`（23 项）：用一个本地 bare 仓库模拟"我建 A、他建 B"，
验证合并后远端与本地双方都拿到了 A 和 B。

> **合并之后面板会多出一句「有 N 个提交没上传」，那是正常的，点一次「上传」就好。**
> 自动合并会在你本地留下一个 merge commit（把两边改动连起来的那一笔），远端还没有它，
> 所以本地确实领先 —— 这不是没同步成功。
>
> 这里曾经有个很难受的毛病：判断「远端有没有新东西」时只比两个 sha 相不相等，
> 而 merge commit 的 sha 和远端**永远**不同。于是那句「远端有新内容」点多少次
> 「下载」都消不掉，看着就像下载根本没生效。现在先问一句「远端那个提交我这儿有了吗」，
> 再配合「本地有几个提交没上传」，两个方向才都说清楚。守着它的是
> `verify-merge.mjs` 的 `[6]` / `[6b]` 两组（真落后时必须报，合并之后必须不报）。

**改同一个武将的同一处 —— 会报冲突，但不会丢东西。** 这时会明确提示「和远端撞车了」，
并且做到三件事：

- 你本地的改动**保持原样**，不会被对方覆盖；
- 工作副本自动退回合并前的状态，**不会留一个半合并的烂摊子**（否则下次点任何按钮都是坏的）；
- 提示里给出下一步怎么走。

**最容易撞的是 `.data\tags.json`**（标签 / 原作表），因为两个人都可能往里加标签。
真撞了就把两边的标签手工并成一份，再点上传。

> 记忆点：**「上传」= 先把对方的合过来、再把我的推上去**，所以它本身也是"同步"。
> 「下载」只把远端拿下来，本地还没推上去的提交它不会替你推（但会提示你去点上传）。

## 八、注意事项

- 服务只监听本机 `127.0.0.1`，局域网内其它设备访问不到（这是有意的：接口能读写磁盘文件，别往外开）。
- 网页保存是**整体覆盖**该武将的 `武将.json`，不做版本管理；重要内容建议自己另外留一份。
- **不要在文件管理器里同时手改同一个 `武将.json`**：网页里如果有未保存的修改，保存时会覆盖掉你的手改。
- 用记事本 / PowerShell 改 JSON 时当心 **UTF-8 BOM**——服务端已做容错，但仍建议直接用网页编辑。
- 素材里若干文件名含**零宽空格**（如 `立绘.png` 实际是 `立绘\u200B.png`）。服务端按清洗后的名字逐级匹配真实文件，网页显示与保存都不受影响；但你自己新建文件时不必模仿这种写法。
- `启动.cmd` / `停止.cmd` **必须保持纯 ASCII**，`start.ps1` / `stop.ps1` **必须保持 UTF-8 with BOM**。这是 cmd.exe 按 ANSI 逐字节解析批处理导致的，改错编码会重现"双击闪退"。
- `.data\原始描述备份\` 是 24 份原始 `描述.txt` 的唯一留存，别删。
